# COLA Dependencies

# NOTE (Linux/NSCC): tensorflow-macos is Apple-Silicon-only and has been
# removed -- plain tensorflow==2.15.0 below is the correct package here.
#
# NOTE (CUDA): probed on a compute node (scripts/probe_gpu.pbs, 2026-08-13):
#   GPU    NVIDIA A100-SXM4-40GB
#   Driver 570.124.06  ->  supports CUDA up to 12.8
# torch 2.13.0 was rejected: it bundles CUDA 13.0.3, one major version above
# the driver ceiling, so it would import fine and then fail at .cuda().
# Pinned to torch 2.5.1 + cu121 instead -- same CUDA 12.x family the previous
# JAX pipeline ran on successfully on this cluster, and numpy-1.x compatible
# so JAX and torch can share one env.
# The cu121 wheels come from PyTorch's own index, not PyPI:
#   pip install torch==2.5.1 torchvision==0.20.1 \
#       --index-url https://download.pytorch.org/whl/cu121
#
# NOTE (numpy): jaxlib==0.4.20 is built against the numpy 1.x ABI, so
# numpy==1.24.3 must be installed LAST -- tensorflow/transformers will
# silently upgrade it otherwise. Symptom of the conflict:
#   AttributeError: _ARRAY_API not found
# If torch 2.13 turns out to require numpy>=2, JAX and torch cannot share
# one env; split into a one-off conversion env (jax/flax/orbax/tf) and a
# training env (torch only). See octo-pytorch/octo_pt_setup.md.
